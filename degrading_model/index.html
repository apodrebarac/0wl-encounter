Practice-based PhD Research — Degrading Model Series

The Degrading Model

A character-level LSTM trained on book-0 and book-1 — two poetry collections that are themselves the output of earlier RNNs trained on family letters. This is a third-generation degradation. The model learns degraded language and degrades it further.

Seed text: your grandmother's letters. Output: something between a letter and a poem. Neither yours nor hers. Between.

01 — Overview

What this is

This is a character-level Recurrent Neural Network — a system that reads text one character at a time, learns its patterns, and generates new text by predicting what comes next. Unlike large language models, it has no knowledge of the world outside your corpus. It knows only what you gave it.

The training data is book-0.pdf and book-1.pdf — two poetry books whose language is already the output of earlier RNNs (F0x and am1) trained on your grandparents' letters. This model trains on that degraded language, producing a third generation: further eroded, further from the source.

The pages of printed model weights (long sequences of numbers embedded inside both books) are included in the training corpus. The new model will occasionally produce number sequences mid-output — the machine's numerical interior surfacing through language. This is intentional.

When you run generation with a seed from your grandmother's letters, the model attempts to continue from her language using patterns it learned from yours. It cannot do this cleanly. The gap between reaching and arriving is the output.

02 — Project files

Files in this project

1_prepare_corpus.py
Extracts text from both PDF books and saves it as corpus.txt. Run once before training.
2_train.py
Trains the LSTM model on the corpus. Saves checkpoints every 10 epochs to the checkpoints/ folder.
3_generate.py
Loads a trained checkpoint and generates text. Takes a seed string and a temperature value.

Python dependencies: torch, pymupdf, numpy.
corpus.txt
Generated by Step 1. The raw training text — 87,616 characters extracted from both books.
vocab.json
Generated by Step 2. Stores the character vocabulary and model settings so the generator can load them.
checkpoints/
Generated by Step 2. Contains saved model states at each checkpoint epoch. Earlier = more degraded.
book-0.pdf
Poems from F0X. Dedicated: "Read them to trees." Training source, book one.
book-1.pdf
Poems from am1. Dedicated: "Read them to a mirror." Training source, book two.

  1. Check Python is installed

    Open Terminal (Applications → Utilities → Terminal) and run:

    python3 --version

    You should see Python 3.x.x. If you see an error, download Python from python.org and install it.

  2. Navigate to the project folder

    cd /Users/anamarijapodrebarac/0wl-encounter/degrading_model

    Or drag the folder onto the Terminal window after typing cd (with a space).

  3. (Recommended) Create a virtual environment

    This keeps the project's libraries separate from everything else on your machine:

    python3 -m venv venv

    Your terminal prompt will change to show (venv). You'll need to run source venv/bin/activate again each time you open a new Terminal window for this project.

    This installs PyTorch, PyMuPDF, and NumPy. May take a few minutes on first run.

  5. Verify installation

    python3 -c "import torch; import fitz; import numpy; print('ready')"

    Should print ready. If you see an error, see Troubleshooting below.

06 — Step 1

Prepare the corpus

This extracts all text from book-0.pdf and book-1.pdf and saves it as corpus.txt. Run it once — you won't need to run it again unless you change the source PDFs. 

python3 1_prepare_corpus.py

You should see output like:

Extracting corpus from poetry books...

Reading: book-0.pdf
  → 43,810 characters extracted
Reading: book-1.pdf
  → 43,799 characters extracted

Total characters: 87,616
Unique characters (vocabulary size): 85

Corpus ready. Run 2_train.py next.

The extraction includes the pages of numbers printed inside both books — the model weights from F0x and am1. The new model will learn those too.

If something goes wrong

If you see ERROR: Cannot find book-0.pdf, check that the PDFs are in the parent folder (0wl-encounter/) and that 1_prepare_corpus.py is in 0wl-encounter/degrading_model/.

07 — Step 2

Train the model

python3 2_train.py

Training will run for 150 epochs by default, printing loss after each one. A checkpoint is saved every 10 epochs inside the checkpoints/ folder. 

Training device: cpu
Running on CPU. Training will be slow. This is expected.

Model parameters: 1,096,277

Settings:
  Hidden size:     256  (memory capacity)
  Layers:          2
  Dropout:         0.3  (degradation rate)
  ...

Epoch    1/150  |  loss: 4.3201  |  42.3s
Epoch    2/150  |  loss: 3.8847  |  41.9s
...

What the loss means

Loss measures how surprised the model is by each character — how much it did not predict what came next. As training progresses, loss decreases: the model becomes less surprised, more knowing of the corpus's patterns.

A partially trained model (high loss, early epoch) produces stranger, more broken output. A more trained model (lower loss, late epoch) produces output closer to your text's rhythms. Neither is better. They are different.

Resuming training

If training is interrupted, resume from the last checkpoint:

python3 2_train.py --resume checkpoints/epoch_0050.pt

How long will it take?

On a typical laptop CPU: 30–90 seconds per epoch. 150 epochs ≈ 1–4 hours total. You can let it run overnight. The script saves checkpoints as it goes — you can start generating after the first 10 epochs if you want an early look.

08 — Step 3

Generate text

python3 3_generate.py

This loads the most recent checkpoint and generates text starting from the seed defined inside the script. Each run produces different output even with the same settings — the sampling process is stochastic.

Using command-line options

You can override settings without editing the file:

# Use a specific checkpoint (e.g. epoch 30, more degraded)
python3 3_generate.py --checkpoint checkpoints/epoch_0030.pt

# Change the temperature
python3 3_generate.py --temperature 1.2

# Change the seed text
python3 3_generate.py --seed "0wl"

# Generate more characters
python3 3_generate.py --length 1200

# Save output to a file
python3 3_generate.py --save output_01.txt

# Combine options
python3 3_generate.py --temperature 0.5 --seed "Dear baka," --save baka_01.txt

The temperature parameter

Temperature is the primary expressive control. It scales the model's probability distribution before sampling each character:

0.3
Faithful, eerie. Recognisable patterns from the corpus repeat closely. The model plays it safe. Close to the source.
0.5
Familiar rhythms, unexpected words. The shape of your language, but slipping.
0.8
Almost-meaning. The default. The balance between recognition and strangeness. Grief that is still legible.
1.0
Standard sampling. No compression or dilation. The model's unmodified distribution.
1.2
Dissociation begins. Language starts to untether from sense. Familiar words in wrong configurations.
1.5
Unmoored. Fragments, reach without arrival. The machine extends past its knowledge.
2.0
Near-collapse. Barely language. Texture more than meaning. The far edge.

Seed text suggestions

# Opens like the Draga bako letter
--seed "Dear baka,"

# The name as a door
--seed "0wl"

# From Bridge Place (book-0)
--seed "Please find me"

# From the corpus itself
--seed "I cannot bring you"

# Emptiness — the model begins from silence
--seed ""

# From your letter
--seed "The machine remembers, and it forgets"

Using an earlier checkpoint

Each checkpoint is a different version of the model — a different moment in its learning. An earlier checkpoint (epoch 20, 30) has learned less and produces more broken output. This is not a failure state. It is a different quality of degradation. 

# Most degraded (very early, barely learned)
python3 3_generate.py --checkpoint checkpoints/epoch_0010.pt

# Mid-training — between learning and forgetting
python3 3_generate.py --checkpoint checkpoints/epoch_0060.pt

# Most formed (latest checkpoint)
python3 3_generate.py  # uses the most recent automatically
09 — Reference

All parameters explained

Training parameters (2_train.py)

Edit these directly inside the SETTINGS section at the top of the file.

Parameter
Default
What it does
HIDDEN_SIZE
256
Memory capacity. How many numbers the model uses to hold its understanding of what it has read. Smaller = more forgetting. Try 128 (more degraded) or 512 (more faithful).
NUM_LAYERS
2
Depth of memory. Two LSTM layers stacked. Layer 1 learns local character patterns, Layer 2 learns higher-level rhythm and structure.
DROPOUT
0.3
Rate of degradation during training. At each step, 30% of connections are randomly severed. The model learns to work with loss built in. 0.0 = no degradation. 0.5 = heavy degradation.
SEQUENCE_LENGTH
100
How many characters the model reads at once. Shorter = more fragmented context, more surprising leaps. Longer = more coherent patterns learned.
NUM_EPOCHS
150
Total training passes through the data. More = more learned. Checkpoints every 10 epochs let you access intermediate states.
LEARNING_RATE
0.002
Step size during learning. Leave at default unless training is unstable (loss fluctuates wildly) — then try 0.001.
BATCH_SIZE
32
Sequences trained simultaneously. Higher = faster but uses more memory. 16 if your machine is slow, 64 if it is fast.
SAVE_EVERY
10
Save a checkpoint every N epochs. Lower = more checkpoints, more intermediate states available.

Generation parameters (3_generate.py)

Edit these directly in the SETTINGS section, or pass them as command-line flags.

Parameter
Default
What it does
TEMPERATURE
0.8
The grief parameter. Controls divergence from learned patterns. 0.3 = faithful. 0.8 = almost-meaning. 1.5 = dissociation. See the temperature scale above.
SEED_TEXT
"Dear baka,"
The opening the model reads before generating. Any string. The model builds hidden state from this before generating.

10 — Architecture

Architecture

Why character-level

The model reads and generates one character at a time — not words, not tokens. This preserves the grain of your writing: the idiosyncratic spacing, the broken grammar, the abrupt line endings. A word-level model would smooth those edges. This one keeps them. Your corpus is already degraded language. This model learns the texture of degradation itself.

Why LSTM, not Transformer

A Transformer (the architecture behind GPT, Claude, most modern language models) processes text by attending to all positions simultaneously. It has no genuine past — it treats time as space, every moment equally accessible.

An LSTM has a hidden state that is carried forward through time. Each character modifies the state, and the state carries influence from earlier characters forward. The past is present, but imperfectly — it degrades as new information arrives. This is the only architecture whose temporal structure is philosophically correct for this project.

The LSTM has a forget gate — a literal architectural mechanism that decides what to discard from memory at each timestep. Not a metaphor. The mechanism itself forgets, by design.

The forget gate

At each character, the LSTM computes four values: input gate (what new information to store), forget gate (what existing memory to discard), cell state (the accumulated memory), and output gate (what to read from memory). The forget gate multiplies the current memory by a number between 0 and 1 — 0 is complete forgetting, 1 is complete retention. The model learns what to forget from the data itself.

Why dropout is structural

During training, 30% of connections are randomly severed at each step. The model learns to represent information redundantly — no single pathway can be relied upon. This means the model's knowledge is distributed and imprecise. The degradation is not added after training. It is trained in.

Third-generation degradation

Book-0 and Book-1 are themselves the outputs of F0x and am1 — RNNs trained on your grandparents' letters. Their language is already once-removed from the source. This model trains on that output, producing output twice-removed. When generation is seeded with a fragment from a grandmother's letter, the result passes through three layers of computational mediation. The distance is the point.

11 — Troubleshooting

Troubleshooting

ModuleNotFoundError: No module named 'fitz'

PyMuPDF is not installed. Run:

pip install pymupdf

ModuleNotFoundError: No module named 'torch'

PyTorch is not installed. Run:

pip install torch

ERROR: Cannot find book-0.pdf

The script expects the PDFs to be one folder up from degrading_model/. Check that your folder structure looks like this:

0wl-encounter/
  book-0.pdf
  book-1.pdf
  degrading_model/
    1_prepare_corpus.py
    2_train.py
    3_generate.py

No checkpoint found

You need to run 2_train.py and wait for the first checkpoint (after epoch 10) before you can generate.

Training is very slow

This is expected on CPU. 150 epochs may take several hours on a laptop. You can reduce NUM_EPOCHS to 50 or 80 for faster results, and generate from those earlier checkpoints.

The output doesn't look right / is pure gibberish

If you are only a few epochs in, this is expected — the model is still learning. Try after epoch 30–50 for legible-but-degraded output. If it is still pure noise at epoch 100+, try lowering TEMPERATURE to 0.5 or 0.3.

Out of memory

Lower BATCH_SIZE to 16 in 2_train.py.

Windows: venv\Scripts\activate gives a permissions error

Open PowerShell as Administrator and run:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Then try activating the virtual environment again.
