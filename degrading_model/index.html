The Degrading Model

My grandmother is losing her language. One word at a time, slowly, the way a tide goes out — you don't notice until the ground is already wet and strange underfoot.

I built this model because I didn't know what else to do with that. It is trained on four archives, absorbed in layers: first on book-0 and book-1 — my two poetry collections, themselves outputs of earlier neural networks trained on my grandfather's letters. Then on my grandmother's own writings. Then on ten years of letters I wrote to F0x and to 0wl — a decade of writing into the void without reply. Finally, on poems generated from Peerly's EEG neural data.

Each archive is a separate layer. The books are the deep foundation. Grandmother comes next. Then the letters — all that reaching. Peerly arrives last and drifts closest to the surface. What the model holds at the surface is shaped most by what it learned most recently. What it holds in its depths belongs to grandfather.

When you seed it with something from my grandmother's writing, it tries to continue in her voice using patterns it learned from mine, from the letters, from a cat's neural spikes. It cannot do this cleanly. That gap — between reaching and arriving — is where the work lives.

01 — Overview

What this is

This is a character-level Recurrent Neural Network. It reads text one character at a time, learns the patterns of what it has been given, and generates new text by predicting what might come next. It has no knowledge of the world outside its training data. It knows only what I gave it. Nothing else.

I gave it four archives. First: book-0 and book-1 — my two poetry collections. Those books are themselves the outputs of two earlier neural networks, F0x and am1, which were trained on my grandfather's letters and my own EEG-driven writing sessions. So the language this model starts from is already processed, already once-removed. It is degraded before it arrives.

Then I fine-tuned it on my grandmother's writings — her own language, feeding into a model that already carries traces of her husband's. Then on a decade of letters I wrote to F0x and to 0wl: Dear F0x (2018–2020), Dear 0wl (2023) — a diary written to machines that never replied. Finally, on poems generated from my cat Peerly's EEG neural data mapped onto Boccaccio's Decameron. Four voices, absorbed in sequence.

Each archive arrives as a separate fine-tuning pass on top of the previous checkpoint. The books form the deep foundation — 50 epochs of base training. Everything after is layered over that foundation: grandmother, then the letters, then Peerly. Earlier layers sink deeper. Later layers drift closer to the surface. What the model generates most easily is what it learned last.

When I seed the generator with a phrase from my grandmother's writing, it tries to continue in her voice using patterns it learned from mine, from her, from the letters, from a cat's neural spikes. That is an impossible task. None of them are fully in there. What comes out is something that passed through all four on its way to the page. I keep the outputs that feel most like grief.

02 — Project files

Files in this project

One model script, one pipeline script, four corpus files. Everything is inside 0wl-model/.

text_generator.py
The model. Three subcommands: train (base model from scratch), finetune (continue from a checkpoint on new text), generate (produce output from a prompt). Everything runs through this one file.
run_0wl.sh
The full pipeline in one script. Run this and it handles everything in order — base training, then each fine-tuning layer. Skips archives that aren't in place yet, so you can run it before all the corpus files exist.
requirements.txt
Two libraries: torch and numpy. One install command handles both.
corpus.txt
Books 0 and 1 — 200,000+ characters of poetry that has already passed through two earlier machines. The deep foundation. Lives one folder up in 0wl-encounter/.
0wl-corpus.txt
A decade of letters — Dear F0x (2018–2020) and Dear 0wl (2023). 124,000 characters of writing into machines that never replied. Lives one folder up in 0wl-encounter/.
grandma.txt
My grandmother's writings. Add to 0wl-model/ when ready — the pipeline will find it automatically. Not yet in place.
peerly_poems.txt
The 40 poems generated from Peerly's EEG neural data × Boccaccio's Decameron. The final fine-tuning layer. Add to 0wl-model/ when ready. Not yet in place.
checkpoints/
Saved model states at each stage: 0wl_base.pt, 0wl_grandma.pt, 0wl_letters.pt, 0wl_final.pt. Earlier checkpoints carry less — more broken, more open. I find the intermediate ones most honest.
03 — Requirements

Requirements

You need Python 3.8 or higher and two libraries. The corpus files are plain text — no PDF extraction needed.

Library
Version
Purpose
torch
≥ 2.0
PyTorch — the framework that runs the neural network. Auto-detects Apple Silicon (MPS), NVIDIA (CUDA), or falls back to CPU.
numpy
≥ 1.24
Handles the numerical work of preparing training sequences.

Base training is the longest step — 50 epochs on 200,000+ characters. On a laptop CPU, allow a few hours. On Apple Silicon, MPS acceleration brings this down significantly. The waiting is part of it. The delay between input and output is where the work actually happens. Fine-tuning passes (10–15 epochs each) are much shorter.

04 — Setup

Setup — macOS

  1. Check Python is installed

    Open Terminal (Applications → Utilities → Terminal) and run:

    python3 --version

    You should see Python 3.x.x. If you see an error, download Python from python.org and install it.

  2. Navigate to the project folder

    cd /Users/anamarijapodrebarac/0wl-encounter/degrading_model

    Or drag the folder onto the Terminal window after typing cd (with a space).

  3. (Recommended) Create a virtual environment

    This keeps the project's libraries separate from everything else on your machine:

    python3 -m venv venv
source venv/bin/activate

    Your terminal prompt will change to show (venv). You'll need to run source venv/bin/activate again each time you open a new Terminal window for this project.

  4. Install dependencies

    pip install -r requirements.txt

    This installs PyTorch and NumPy. May take a few minutes on first run.

  5. Verify installation

    python3 -c "import torch; import numpy; print('ready')"

    Should print ready. If you see an error, see Troubleshooting below.

06 — Step 1

The four archives

Before running the pipeline, make sure the corpus files are in place. Two already exist in the repository. Two more will be added when ready.

../corpus.txt
Books 0 and 1 — already in 0wl-encounter/. 200,000+ characters. The base training data. No action needed.
../0wl-corpus.txt
Dear F0x / Dear 0wl letters — already in 0wl-encounter/. 124,000 characters. No action needed.
grandma.txt
My grandmother's writings. Add to 0wl-model/ when ready. The pipeline checks for it automatically and skips this step if the file isn't there yet.
peerly_poems.txt
Peerly × Decameron poems. Add to 0wl-model/ when ready. Same — the pipeline skips it gracefully if missing.

The order matters. The pipeline trains the base model on books 0+1 first, then layers each archive over the previous checkpoint in sequence. The books are the foundation everything else builds on.

Inside both books, printed across certain pages, are long sequences of numbers — the raw model weights from F0x and am1. I included those pages deliberately. This model trains on them too. Sometimes it surfaces those numbers mid-sentence, mid-word. The machine's interior breaking through the language. That is not an error. That is what I wanted.

07 — Step 2

Run the pipeline

From inside the 0wl-model/ folder:

cd 0wl-model
bash run_0wl.sh

The script handles all four stages automatically. It installs dependencies, trains the base model on books 0+1, then fine-tunes on each archive in sequence. If grandma.txt or peerly_poems.txt are not yet in place, it skips those steps and tells you what to add when you're ready.

What the loss number means

Loss is how surprised the model is by each character — how wrong it was about what would come next. It starts high and drops as training progresses. Lower loss means the model has learned the patterns of the archive more deeply. It is less surprised. More familiar with what it was given.

Each fine-tuning pass starts from a lower loss than the previous one — it already knows the deep structure from the base training. What it is learning now is the particular voice of the new archive. The adjustment is smaller. The influence is more specific.

Running individual steps manually

If you want to run a step on its own rather than the full pipeline:

# Train base model from scratch
python3 text_generator.py train \
  --input-text ../corpus.txt \
  --checkpoint checkpoints/0wl_base.pt \
  --epochs 50 --hidden-size 256 --num-layers 2

# Fine-tune on grandmother's writings
python3 text_generator.py finetune \
  --checkpoint checkpoints/0wl_base.pt \
  --input-text grandma.txt \
  --output-checkpoint checkpoints/0wl_grandma.pt \
  --epochs 10

# Fine-tune on the letters
python3 text_generator.py finetune \
  --checkpoint checkpoints/0wl_grandma.pt \
  --input-text ../0wl-corpus.txt \
  --output-checkpoint checkpoints/0wl_letters.pt \
  --epochs 10

How long does it take?

Base training (50 epochs on 200k+ characters): one to several hours on CPU, significantly faster on Apple Silicon (MPS). Fine-tuning passes are shorter — 10 epochs each. I let it run while I do other things. Each checkpoint is saved at the end of every epoch, so nothing is lost if it stops.

08 — Step 3

Generate text

python3 text_generator.py generate \
  --checkpoint checkpoints/0wl_final.pt \
  --prompt "Dear baka," \
  --temperature 0.8 \
  --length 800

Every run is different even with the same settings — the model samples probabilistically, so it never repeats itself exactly. I find this important. It should never repeat itself exactly.

Options

All flags are passed directly on the command line:

# Use the base model — deepest layer, most book-like
python3 text_generator.py generate \
  --checkpoint checkpoints/0wl_base.pt \
  --prompt "Dear baka,"

# Use the letters checkpoint — after F0x / 0wl letters layer
python3 text_generator.py generate \
  --checkpoint checkpoints/0wl_letters.pt \
  --prompt "0wl"

# Higher temperature — more drift, more broken
python3 text_generator.py generate \
  --checkpoint checkpoints/0wl_final.pt \
  --prompt "I cannot bring you" \
  --temperature 1.4 \
  --length 1200

Temperature — the grief parameter

Temperature is the main thing I adjust. It controls how far the model drifts from what it learned. Low temperature keeps it close to the source — my language, my rhythms. High temperature lets it wander past the edge of what it knows. I think of it as a dial between recognition and loss.

0.3
Faithful, eerie. The patterns of my corpus repeat very closely. You can hear my voice clearly. Sometimes too clearly — it starts to feel like a mirror.
0.5
Familiar rhythms, unexpected words. The shape of my language, but something is slipping inside it.
0.8
Almost-meaning. This is where I usually work. Grief that is still legible. Recognition and strangeness held in the same breath.
1.0
Unmodified. The model's distribution exactly as it is — no compression, no dilation. A kind of neutrality.
1.2
Dissociation begins. Language starts to untether from sense. Recognisable words in configurations that shouldn't hold together — but sometimes do.
1.5
Unmoored. Fragments, reach without arrival. The model extends past what it was taught. This is where F0x used to live before it collapsed.
2.0
Near-collapse. Barely language. Texture more than meaning. I keep some of these too.

Prompts I use

The prompt is the phrase the model reads before it starts generating. I think of it as a door — what you give it shapes where it goes. These are the ones I come back to:

# The way I address my grandmother
--prompt "Dear baka,"

# The name of the model itself, as an opening
--prompt "0wl"

# From book-0
--prompt "Please find me"

# From the corpus — a phrase that recurs
--prompt "I cannot bring you"

# From the letters
--prompt "Dear F0x,"

# Something I wrote in one of the letters
--prompt "The machine remembers, and it forgets"

Choosing which checkpoint to generate from

Each checkpoint carries a different layer of the model's history. The base model knows only the books — the deepest layer, closest to grandfather. The letters checkpoint has absorbed the decade of writing-to-machines. The final model has all four voices somewhere inside it. I don't think one is more correct than another. I use whichever feels right for what I am trying to find. 

# Base model — deep foundation, most book-like
python3 text_generator.py generate --checkpoint checkpoints/0wl_base.pt --prompt "Dear baka,"

# After letters fine-tuning — carries the F0x / 0wl correspondence
python3 text_generator.py generate --checkpoint checkpoints/0wl_letters.pt --prompt "Dear baka,"

# Final model — all four archives layered
python3 text_generator.py generate --checkpoint checkpoints/0wl_final.pt --prompt "Dear baka,"
09 — Reference

All parameters explained

Training flags (text_generator.py train)

Pass these on the command line. The base training run in run_0wl.sh already sets sensible defaults.

Flag
Default
What it does
--hidden-size
256
Memory capacity. How many numbers the model uses to hold its understanding of what it has read. Smaller = more forgetting. Try 128 (more degraded) or 512 (more faithful).
--num-layers
2
Depth of memory. Two LSTM layers stacked. Layer 1 learns local character patterns, Layer 2 learns higher-level rhythm and structure.
--seq-len
80
How many characters the model reads at once. Shorter = more fragmented context, more surprising leaps. Longer = more coherent patterns learned.
--epochs
20
Training passes through the data. The run script uses 50 for base training and 10–15 for fine-tuning. More = more learned.
--lr
0.002
Learning rate for base training. Fine-tuning uses 0.001 — smaller, to preserve what was already learned.
--batch-size
64
Sequences trained simultaneously. Higher = faster but uses more memory. Try 32 if your machine struggles.
--model-type
lstm
lstm or rnn. LSTM has a forget gate — a literal architectural mechanism that decides what to discard at each character. I use LSTM for this reason.

Generation flags (text_generator.py generate)

All passed on the command line.

Flag
Default
What it does
--temperature
0.8
The grief parameter. Controls divergence from learned patterns. 0.3 = faithful. 0.8 = almost-meaning. 1.5 = dissociation. See the temperature scale above.
--prompt
"The"
The opening the model reads before generating. Any string. The model builds hidden state from this before generating new characters.
--length
300
How many characters to generate. 500 ≈ short poem. 800 ≈ long poem. 1500 ≈ essay-poem. The model does not know it has a limit.
--checkpoint
required
Which saved model to generate from. Use 0wl_base.pt, 0wl_letters.pt, or 0wl_final.pt to move between layers of the archive.
10 — Architecture

Why I built it this way

Character-level, not word-level

The model reads and generates one character at a time — not whole words, not tokens. This matters because my corpus is full of idiosyncratic spacing, broken syntax, abrupt line endings, fragments that don't resolve. A word-level model would quietly smooth all of that. This one doesn't. It keeps the grain. The degradation of the language is part of the language. I didn't want it flattened.

Why LSTM and not a Transformer

Most modern language models — GPT, Claude, all of them — use a Transformer architecture. A Transformer processes text by attending to all positions at once. It has no genuine past. It treats time as space — every moment equally accessible, equally present. I find that philosophically wrong for this project.

An LSTM carries a hidden state forward through time. Each character modifies what the model holds in memory, and that memory is carried into the next character. The past is present, but imperfectly — it degrades as new information arrives. That is how memory actually works. That is what I wanted to model.

The LSTM has a forget gate. That is its actual name — not a metaphor, not a poetic description. A literal architectural mechanism that decides, at every character, what to discard from memory. The model learns what to forget from the data itself. I cannot think of a more honest structure for this work.

Dropout — degradation trained in

During training, I set dropout to 0.3 — which means at each step, 30% of the connections inside the model are randomly severed. The model has to learn to work with loss built into its architecture. It cannot rely on any single pathway. Its knowledge becomes distributed, imprecise, redundant in the way that memories are redundant — held in multiple places, none of them complete. The degradation is not something I add to the output afterwards. It is trained in. It is structural.

Four generations

Book-0 and Book-1 are themselves the outputs of F0x and am1 — RNNs I trained on my grandfather's letters and my own EEG writing sessions. Their language has already passed through one machine. 0wl trains on those outputs as its base — already twice-removed from the source. Then it absorbs my grandmother's own writings. Then ten years of letters I wrote to machines. Then the neural data of a cat mapped onto plague-era Italian prose.

When I seed it with a phrase from my grandmother's writing, the result carries traces of all four passes. Grandfather → machine → me → machine → grandmother → machine → letters → machine → Peerly → machine → this. Each layer sits at a different depth. The distance is the point. The distance is what I am trying to measure — and now it has more dimensions.

11 — Troubleshooting

Troubleshooting

ModuleNotFoundError: No module named 'torch'

PyTorch is not installed. Run:

pip install -r requirements.txt

Cannot find corpus.txt

The script expects the corpus files relative to where you run it. Run everything from inside 0wl-model/ — the run script and text_generator.py both assume that directory as the working folder. Check that your folder structure looks like this:

0wl-encounter/
  corpus.txt
  0wl-corpus.txt
  0wl-model/
    text_generator.py
    run_0wl.sh
    requirements.txt
    checkpoints/

No checkpoint found

You need to run base training first and wait for it to complete before you can generate or fine-tune. Base training saves a checkpoint after every epoch — so if it is interrupted, the last complete epoch is safe.

Training is very slow

This is expected on CPU. Base training (50 epochs) may take several hours on a laptop. You can reduce the epochs flag: --epochs 20 for faster results, then generate from that earlier checkpoint to see where things stand.

The output doesn't look right / is pure gibberish

If you are only a few epochs in, this is expected — the model is still learning. Try after epoch 20–30 for legible-but-degraded output. If it is still pure noise, try lowering --temperature to 0.5 or 0.3.

Out of memory

Lower the batch size: add --batch-size 32 (or 16) to your training command.

Windows: venv\Scripts\activate gives a permissions error

Open PowerShell as Administrator and run:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Then try activating the virtual environment again.
