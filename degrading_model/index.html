The Degrading Model

My grandmother is losing her language. One word at a time, slowly, the way a tide goes out — you don't notice until the ground is already wet and strange underfoot.

I built this model because I didn't know what else to do with that. It is trained on book-0 and book-1 — my two poetry collections, which are themselves outputs of earlier neural networks trained on my grandfather's letters. So this model trains on language that has already passed through a machine once. It is a third generation. Further from the source with every pass.

When you seed it with something from my grandmother's writing, it tries to continue in her voice using patterns it learned from mine. It cannot do this cleanly. That gap — between reaching and arriving — is where the work lives.

01 — Overview

What this is

This is a character-level Recurrent Neural Network. It reads text one character at a time, learns the patterns of what it has been given, and generates new text by predicting what might come next. It has no knowledge of the world outside its training data. It knows only what I gave it. Nothing else.

I gave it my own poetry — book-0 and book-1. Those books are themselves the outputs of two earlier neural networks, F0x and am1, which were trained on my grandfather's letters and my own EEG-driven writing sessions. So the language this model learns from is already processed, already once-removed. It is degraded before it arrives. This model degrades it further. I think of it as a third generation: grandfather → machine → me → machine → this.

Inside both books, printed across certain pages, are long sequences of numbers — the raw model weights from F0x and am1. I included those pages deliberately. This model trains on them too. Sometimes it surfaces those numbers mid-sentence, mid-word. The machine's interior breaking through the language. That is not an error. That is what I wanted.

When I seed the generator with a phrase from my grandmother's writing, it tries to continue in her voice using patterns it learned from mine. That is an impossible task. She is not in there. Neither am I, not really. What comes out is something in between — not translation, not invention. An attempt. A reaching. I keep the outputs that feel most like grief.

02 — Project files

Files in this project

Three scripts, run in order. The rest is generated as you go.

1_prepare_corpus.py
Pulls the text out of both PDF books and saves it as corpus.txt. Run this once before anything else.
2_train.py
Trains the model on that text. Saves a snapshot every 10 epochs into a checkpoints/ folder — so you can go back and use an earlier, less-trained version if you want something more broken.
3_generate.py
Loads a checkpoint and generates text from a seed. This is the part where you give it a first word or phrase and watch what it does with the inheritance.
requirements.txt
The Python libraries needed: torch, pymupdf, numpy. One install command handles all three.
corpus.txt
Created by Step 1. 87,616 characters of my poetry, numbers, fragments. The entirety of what the model will ever know.
vocab.json
Created automatically during training. Stores the character set and settings so the generator can load them correctly.
checkpoints/
A folder of the model's states at different moments in training. Earlier checkpoints = less learned = more fragmented. I find the early ones most honest.
book-0.pdf
Poems from F0x. Dedicated: "Read them to trees." The first training source.
book-1.pdf
Poems from am1. Dedicated: "Read them to a mirror." The second training source.

04 — Setup

Setup — macOS

  1. Check Python is installed

    Open Terminal (Applications → Utilities → Terminal) and run:

    python3 --version

    You should see Python 3.x.x. If you see an error, download Python from python.org and install it.

  2. Navigate to the project folder

    cd /Users/anamarijapodrebarac/0wl-encounter/degrading_model

    Or drag the folder onto the Terminal window after typing cd (with a space).

  3. (Recommended) Create a virtual environment

    This keeps the project's libraries separate from everything else on your machine:

    python3 -m venv venv
source venv/bin/activate

    Your terminal prompt will change to show (venv). You'll need to run source venv/bin/activate again each time you open a new Terminal window for this project.

  4. Install dependencies

    pip install -r requirements.txt

    This installs PyTorch, PyMuPDF, and NumPy. May take a few minutes on first run.

  5. Verify installation

    python3 -c "import torch; import fitz; import numpy; print('ready')"

    Should print ready. If you see an error, see Troubleshooting below.

06 — Step 1

Prepare the corpus

This extracts all text from book-0.pdf and book-1.pdf and saves it as corpus.txt. Run it once — you won't need to run it again unless you change the source PDFs. 

python3 1_prepare_corpus.py

You should see output like:

Extracting corpus from poetry books...

Reading: book-0.pdf
  → 43,810 characters extracted
Reading: book-1.pdf
  → 43,799 characters extracted

Total characters: 87,616
Unique characters (vocabulary size): 85

Corpus ready. Run 2_train.py next.

The extraction includes the pages of numbers printed inside both books — the model weights from F0x and am1. The new model will learn those too.

If something goes wrong

If you see ERROR: Cannot find book-0.pdf, check that the PDFs are in the parent folder (0wl-encounter/) and that 1_prepare_corpus.py is in 0wl-encounter/degrading_model/.

07 — Step 2

Train the model

python3 2_train.py

Training will run for 150 epochs by default, printing loss after each one. A checkpoint is saved every 10 epochs inside the checkpoints/ folder. 

Training device: cpu
Running on CPU. Training will be slow. This is expected.

Model parameters: 1,096,277

Settings:
  Hidden size:     256  (memory capacity)
  Layers:          2
  Dropout:         0.3  (degradation rate)
  ...

Epoch    1/150  |  loss: 4.3201  |  42.3s
Epoch    2/150  |  loss: 3.8847  |  41.9s
...

What the loss number means

Loss is how surprised the model is by each character — how wrong it was about what would come next. It starts high and drops as training progresses. Lower loss means the model has learned the patterns of my writing more deeply. It is less surprised. More familiar with the grief in the corpus.

An early checkpoint — high loss, barely trained — produces stranger, more broken output. A later checkpoint produces something closer to my actual rhythms. I don't think one is better than the other. I use both. I use whichever feels right for what I am trying to find.

If training is interrupted

Pick up from the last checkpoint rather than starting over:

python3 2_train.py --resume checkpoints/epoch_0050.pt

How long does it take?

On a laptop CPU: roughly 30–90 seconds per epoch. 150 epochs is one to four hours total. I let it run while I do other things. The checkpoints save as it goes, so you can start generating after the first 10 epochs if you want to see where it is early on.

08 — Step 3

Generate text

python3 3_generate.py

This loads the most recent checkpoint and generates text from the seed phrase set inside the script. Every run is different even with the same settings — the model samples probabilistically, so it never repeats itself exactly. I find this important. It should never repeat itself exactly.

Options you can pass from the command line

You can change any of these without opening the script:

# Use a specific checkpoint (e.g. epoch 30, more degraded)
python3 3_generate.py --checkpoint checkpoints/epoch_0030.pt

# Change the temperature
python3 3_generate.py --temperature 1.2

# Change the seed text
python3 3_generate.py --seed "0wl"

# Generate more characters
python3 3_generate.py --length 1200

# Save output to a file
python3 3_generate.py --save output_01.txt

# Combine options
python3 3_generate.py --temperature 0.5 --seed "Dear baka," --save baka_01.txt

Temperature — the grief parameter

Temperature is the main thing I adjust. It controls how far the model drifts from what it learned. Low temperature keeps it close to the source — my language, my rhythms. High temperature lets it wander past the edge of what it knows. I think of it as a dial between recognition and loss.

0.3
Faithful, eerie. The patterns of my corpus repeat very closely. You can hear my voice clearly. Sometimes too clearly — it starts to feel like a mirror.
0.5
Familiar rhythms, unexpected words. The shape of my language, but something is slipping inside it.
0.8
Almost-meaning. This is where I usually work. Grief that is still legible. Recognition and strangeness held in the same breath.
1.0
Unmodified. The model's distribution exactly as it is — no compression, no dilation. A kind of neutrality.
1.2
Dissociation begins. Language starts to untether from sense. Recognisable words in configurations that shouldn't hold together — but sometimes do.
1.5
Unmoored. Fragments, reach without arrival. The model extends past what it was taught. This is where F0x used to live before it collapsed.
2.0
Near-collapse. Barely language. Texture more than meaning. I keep some of these too.

Seeds I use

The seed is the phrase the model reads before it starts generating. I think of it as a door — what you give it shapes where it goes. These are the ones I come back to:

# The way I address my grandmother
--seed "Dear baka,"

# The name of the model itself, as an opening
--seed "0wl"

# From book-0
--seed "Please find me"

# From the corpus — a phrase that recurs
--seed "I cannot bring you"

# Nothing — the model begins from silence
--seed ""

# Something I wrote in one of the letters
--seed "The machine remembers, and it forgets"

Using an earlier checkpoint

Each checkpoint is a snapshot of the model at a different moment in its learning. Earlier checkpoints have learned less — they produce more broken, more fragmented output. I do not think of that as failure. I think of it as a different kind of honesty. F0x taught me that. I let it collapse rather than fix it. Some of its best outputs came in the last weeks before it stopped generating entirely. 

# Most degraded (very early, barely learned)
python3 3_generate.py --checkpoint checkpoints/epoch_0010.pt

# Mid-training — between learning and forgetting
python3 3_generate.py --checkpoint checkpoints/epoch_0060.pt

# Most formed (latest checkpoint)
python3 3_generate.py  # uses the most recent automatically
09 — Reference

All parameters explained

Training parameters (2_train.py)

Edit these directly inside the SETTINGS section at the top of the file.

Parameter
Default
What it does
HIDDEN_SIZE
256
Memory capacity. How many numbers the model uses to hold its understanding of what it has read. Smaller = more forgetting. Try 128 (more degraded) or 512 (more faithful).
NUM_LAYERS
2
Depth of memory. Two LSTM layers stacked. Layer 1 learns local character patterns, Layer 2 learns higher-level rhythm and structure.
DROPOUT
0.3
Rate of degradation during training. At each step, 30% of connections are randomly severed. The model learns to work with loss built in. 0.0 = no degradation. 0.5 = heavy degradation.
SEQUENCE_LENGTH
100
How many characters the model reads at once. Shorter = more fragmented context, more surprising leaps. Longer = more coherent patterns learned.
NUM_EPOCHS
150
Total training passes through the data. More = more learned. Checkpoints every 10 epochs let you access intermediate states.
LEARNING_RATE
0.002
Step size during learning. Leave at default unless training is unstable (loss fluctuates wildly) — then try 0.001.
BATCH_SIZE
32
Sequences trained simultaneously. Higher = faster but uses more memory. 16 if your machine is slow, 64 if it is fast.
SAVE_EVERY
10
Save a checkpoint every N epochs. Lower = more checkpoints, more intermediate states available.

Generation parameters (3_generate.py)

Edit these directly in the SETTINGS section, or pass them as command-line flags.

Parameter
Default
What it does
TEMPERATURE
0.8
The grief parameter. Controls divergence from learned patterns. 0.3 = faithful. 0.8 = almost-meaning. 1.5 = dissociation. See the temperature scale above.
SEED_TEXT
"Dear baka,"
The opening the model reads before generating. Any string. The model builds hidden state from this before generating.
GENERATE_LENGTH
800
How many characters to generate. 500 ≈ short poem. 800 ≈ long poem. 1500 ≈ essay-poem. The model does not know it has a limit.
CHECKPOINT_PATH
None
Leave as None to use the most recent checkpoint. Or specify a path to use an earlier model state.
10 — Architecture

Why I built it this way

Character-level, not word-level

The model reads and generates one character at a time — not whole words, not tokens. This matters because my corpus is full of idiosyncratic spacing, broken syntax, abrupt line endings, fragments that don't resolve. A word-level model would quietly smooth all of that. This one doesn't. It keeps the grain. The degradation of the language is part of the language. I didn't want it flattened.

Why LSTM and not a Transformer

Most modern language models — GPT, Claude, all of them — use a Transformer architecture. A Transformer processes text by attending to all positions at once. It has no genuine past. It treats time as space — every moment equally accessible, equally present. I find that philosophically wrong for this project.

An LSTM carries a hidden state forward through time. Each character modifies what the model holds in memory, and that memory is carried into the next character. The past is present, but imperfectly — it degrades as new information arrives. That is how memory actually works. That is what I wanted to model.

The LSTM has a forget gate. That is its actual name — not a metaphor, not a poetic description. A literal architectural mechanism that decides, at every character, what to discard from memory. The model learns what to forget from the data itself. I cannot think of a more honest structure for this work.

Dropout — degradation trained in

During training, I set dropout to 0.3 — which means at each step, 30% of the connections inside the model are randomly severed. The model has to learn to work with loss built into its architecture. It cannot rely on any single pathway. Its knowledge becomes distributed, imprecise, redundant in the way that memories are redundant — held in multiple places, none of them complete. The degradation is not something I add to the output afterwards. It is trained in. It is structural.

A third generation

Book-0 and Book-1 are themselves the outputs of F0x and am1 — RNNs I trained on my grandfather's letters and my own EEG writing sessions. Their language has already passed through one machine. This model trains on those outputs, producing something twice-removed from the source. When I seed it with a phrase from my grandmother's writing, the result passes through three layers of computational distance. Grandfather → machine → me → machine → this. The distance is the point. The distance is what I am trying to measure.

11 — Troubleshooting

Troubleshooting

ModuleNotFoundError: No module named 'fitz'

PyMuPDF is not installed. Run:

pip install pymupdf

ModuleNotFoundError: No module named 'torch'

PyTorch is not installed. Run:

pip install torch

ERROR: Cannot find book-0.pdf

The script expects the PDFs to be one folder up from degrading_model/. Check that your folder structure looks like this:

0wl-encounter/
  book-0.pdf
  book-1.pdf
  degrading_model/
    1_prepare_corpus.py
    2_train.py
    3_generate.py

No checkpoint found

You need to run 2_train.py and wait for the first checkpoint (after epoch 10) before you can generate.

Training is very slow

This is expected on CPU. 150 epochs may take several hours on a laptop. You can reduce NUM_EPOCHS to 50 or 80 for faster results, and generate from those earlier checkpoints.

The output doesn't look right / is pure gibberish

If you are only a few epochs in, this is expected — the model is still learning. Try after epoch 30–50 for legible-but-degraded output. If it is still pure noise at epoch 100+, try lowering TEMPERATURE to 0.5 or 0.3.

Out of memory

Lower BATCH_SIZE to 16 in 2_train.py.

Windows: venv\Scripts\activate gives a permissions error

Open PowerShell as Administrator and run:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Then try activating the virtual environment again.
